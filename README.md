# Telegram Quest

Приватный Telegram-квест на TypeScript и Node.js 24. Игровая история исполняется Ink runtime; текущий сюжет и прогресс хранятся в Turso.

## Что работает

- `api/webhook.ts` — Vercel POST entrypoint для grammY webhook. Обработчик отклоняет не-POST запросы и проверяет webhook secret до инициализации приложения.
- `internal/bootstrap.ts` — лениво поднимает Turso, применяет миграции и создаёт зависимости приложения; успешный bootstrap переиспользуется внутри процесса.
- `internal/adapters/turso/` — каталог квестов, публикация текущего Ink-сюжета, метаданные, сессии и схема базы версии 4.
- `internal/adapters/ink/` — Ink runtime, компилятор публикации и исходник со скомпилированной историей встроенного демо.
- `internal/adapters/telegram/private-quest.ts` — личный каталог и прохождения, сцены и выборы, пауза/продолжение, остановка, перезапуск и история с откатом.
- `internal/adapters/telegram/menu-presenter.ts` и `scene-presenter.ts` — показывают текстовые и фотоэкраны, сохраняя кнопки и предварительные фрагменты сцен.
- `internal/app/sessions.ts` — операции сессий, проверка владельца и версии состояния, применение выборов и переходов.

В Telegram доступны команды `/start` и `/menu` для меню, `/quests` для каталога и `/sessions` для сохранённых прохождений. Каталог содержит встроенный демонстрационный квест «Две двери». Действия с прохождением доступны его владельцу; остановка, перезапуск и откат требуют второго подтверждения. Старые кнопки отклоняются по версии состояния.

Хранилище сессий поддерживает также групповые сессии, дедлайны и голосования. Групповой интерфейс, запуск таймеров и администрирование в этом приложении не реализованы.

## Конфигурация и инициализация

Webhook требует `TELEGRAM_BOT_TOKEN` и `TELEGRAM_WEBHOOK_SECRET`. Для Turso нужны `TURSO_DATABASE_URL` и `TURSO_AUTH_TOKEN`. После проверки валидного POST webhook bootstrap подключается к базе, автоматически применяет недостающие миграции и добавляет демо, только если его ещё нет. Существующие записи демо не перезаписываются. Ошибка инициализации возвращает webhook-ответ `503`; SQL и секреты клиенту не передаются.

Версия схемы хранится в служебной таблице `quest_schema_version`. Существующие базы со старым `PRAGMA user_version` перед переходом проверяются по полной структуре; неизвестная схема не изменяется. После создания служебной таблицы версии приложения, которые о ней не знают, не смогут открыть эту базу. При восстановлении используйте версию с поддержкой таблицы; не переключайте deployment на старый код без совместимого плана восстановления данных.

Production разворачивается на Vercel из ветки `main`; стабильный webhook — `https://telegram-quest.vercel.app/api/webhook`. В настройках Production задаются четыре перечисленные выше переменные, а Telegram webhook использует тот же секрет и принимает `message` и `callback_query`. Состояние доставки можно проверить вызовом `getWebhookInfo` через авторизованный клиент Telegram Bot API; проверяйте адрес, ожидающие обновления и последнюю ошибку, не выводя токен. Перед сменой webhook сохраните прежний адрес и не сбрасывайте очередь обновлений.

## Ink-история

Исходник встроенного демо и скомпилированная Ink-история находятся в `internal/adapters/ink/fixtures/`. Пересобрать JSON закреплённой версией `inkjs-compiler`:

```sh
npx inkjs-compiler -o internal/adapters/ink/fixtures/demo.ink.json internal/adapters/ink/fixtures/demo.ink
```

## Публикация квеста

Автор хранит исходники книги в отдельной папке с `story.ink` и `quest.json`. Пример манифеста:

```json
{
  "id": "two-doors",
  "title": "Две двери",
  "description": "Короткая история",
  "genre": "Мистика",
  "available": true,
  "metadata": {
    "cover": { "kind": "image", "value": "https://assets.example/cover.jpg" },
    "corridor_note": { "kind": "text", "value": "На стене видны царапины." }
  }
}
```

`id` содержит 1–32 символа из `a-z`, `0-9`, `_` и `-`. Имена метаданных содержат 1–64 символа из `a-z`, `0-9`, `_`, `.` и `-`. Для `image` требуется HTTPS URL без учётных данных и локального hostname; `text` хранит обычный текст. `assets.example` — пример адреса, его нужно заменить на доступный автору URL изображения.

Полная публикация собирает CLI, компилирует `story.ink` установленным `inkjs`, проверяет manifest и compiled JSON, затем одной транзакцией создаёт или обновляет квест и указанные метаданные:

```sh
npm run quest:publish -- ./books/two-doors
```

Все `INCLUDE`-файлы должны находиться внутри папки книги. Компиляция и проверка входов завершаются до начала записи. Повторная публикация с тем же `id` заменяет текущий сюжет, не создавая версии квеста.

`--metadata-only` читает только `quest.json`: обновляет описательные поля существующего квеста и перечисленные метаданные, не открывая `story.ink` и не изменяя сохранённый сюжет или прогресс. Отсутствующий в `metadata` ключ остаётся без изменений; значение `null` удаляет только запись с этим именем.

```sh
npm run quest:publish -- ./books/two-doors --metadata-only
```

Глобальные метаданные меню публикуются из отдельного JSON-файла с полем `metadata`. Они записываются в namespace без `quest_id`:

```json
{
  "metadata": {
    "menu.main.banner": { "kind": "image", "value": "https://assets.example/menu.jpg" }
  }
}
```

```sh
npm run quest:publish -- --menu ./menu.json
```

Production-сборка в Vercel применяет этот файл автоматически. Preview-сборки не записывают метаданные в общую production-базу.

Для проверки папки книги перед публикацией добавьте `--dry-run`. Этот режим собирает и запускает скомпилированный CLI, проверяет manifest и компилирует сюжет, но не подключается к базе и не требует Turso credentials. Для режима `--metadata-only --dry-run` файл `story.ink` не читается. Для реальной публикации задайте `TURSO_DATABASE_URL` и `TURSO_AUTH_TOKEN`; CLI требует готовую схему v4 и не запускает миграции самостоятельно. Миграции применяются при обычном bootstrap приложения.

Ключи `menu.main.banner`, `menu.quests.banner` и `menu.sessions.banner` оформляют соответствующие экраны; `cover` задаёт изображение карточки квеста. В Ink теги `asset:<name>` подключают изображение или дополнительный текст сцены в пространстве текущего квеста. Метаданные читаются при каждом показе, поэтому изменение URL действует при следующем открытии сцены или экрана. Используется одно фото без `parse_mode`: caption ограничен 1024 Unicode-символами, более длинный текст отправляется целиком после фотографии сообщениями до 4096 символов, а клавиатура помещается под последним текстовым сообщением.

## Команды разработки

- `npm ci` — установить версии зависимостей из lock-файла.
- `npm run typecheck` — проверить TypeScript-типы.
- `npm test` — запустить тесты.
